Rules shared by every widget

  • The backend derives site, environment, actor, project, request, request type, module and license from trusted Forge/Jira context.
  • A portal location is checked again at runtime; registry compatibility alone is not authorization.
  • Missing values, capabilities or source failures stay local to the widget and do not expose privileged data.
  • Customer aggregate widgets never return matching request rows, issue keys, summaries, people, comments, organizations or field values from other requests.
  • Actions require an authenticated current customer, active license, visible published widget, current Jira/JSM permission, compatible workflow, confirmation, idempotency and rate limits.
  • New widgets use the compact borderless JSM-native appearance unless an administrator explicitly selects another validated preset.

For configuration workflow, preview, publication and acceptance, return to the complete user guide. For a missing or disabled widget, use Troubleshooting.
