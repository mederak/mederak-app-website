Data Residency

Customer Portal Toolkit stores in-scope App data in Atlassian Forge hosted storage and does not use a vendor-hosted remote or external App database.

Persistent data

Forge Custom Entity Store and KVS, scoped to the App installation.

Remote storage

None.

Hosted compute

Atlassian Forge functions, scheduled/async services and optional Forge LLM.

Platform signal

The production version passes Runs on Atlassian eligibility.

Forge hosted storage

Atlassian states that Forge apps storing all in-scope End-User Data exclusively in persistent Forge hosted storage are eligible for pinned data residency. When an eligible App is installed on an Atlassian product pinned to a supported location, Forge hosted storage follows the host product's pinned location. If the host product is migrated between supported locations, Atlassian manages migration of eligible Forge hosted storage.

Supported locations

At the verification date, Atlassian lists Global, Australia, Canada, EU, Germany, India, Japan, Singapore, South Korea, Switzerland, United Kingdom and USA for Forge hosted storage. Atlassian may add, remove or change locations and underlying regions. The customer's authoritative status is the Atlassian Administration data residency view and current Forge data residency documentation.

Compute and supporting services

Atlassian aims to execute Forge invocations in the same location as the host Atlassian product, but documents that some invocations may run elsewhere for platform capabilities, reliability, security or fraud prevention. Platform logging, metrics, async services, Marketplace operations and optional Preview services such as Forge LLM may have service-specific residency or availability behavior. Customers with strict requirements should assess the current Atlassian documentation before enabling optional AI.

No vendor remote or egress

The App manifest declares no Forge Remote, external fetch domain, third-party product analytics or End-User Data egress. Mederak Apps therefore does not choose a separate region for an App database and does not copy customer Jira content into vendor infrastructure. Public website and support processing are separate and described in Subprocessors.

Migration, backup and deletion

Atlassian controls Forge realm pinning, migration, backup, recovery and underlying physical deletion. The App does not provide a customer-restorable backup or cross-site configuration export/import in version 1.0. Atlassian currently documents a 28-day hosted-storage retention period after uninstall, and reinstall does not automatically restore the previous installation's data. See Uninstall and Data Deletion.

Limitations

This statement does not promise support for every Atlassian location, government cloud, isolated cloud, plan, migration flow or Preview service. A Runs on Atlassian or PINNED signal is not a legal certification. The current Atlassian admin view and published platform documentation control the platform status for a specific site.
